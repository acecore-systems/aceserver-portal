휴대폰, 태블릿, Windows, 콘솔의 베드락 친구를 자신의 Java 서버에 초대하려면 Java 서버에 Geyser와 Floodgate를 설치하는 구성이 실용적입니다. Geyser는 베드락 연결을 Java 서버로 이어 주고, Floodgate는 서버가 베드락 계정을 안전하게 식별할 수 있게 합니다.

중요한 점은 베드락 친구를 받기 위해 Java 계정 인증을 꺼서는 안 된다는 것입니다. 이 안내는 Java 인증과 초대 전용 상태를 유지하는 것에서 시작합니다. Java와 베드락은 조작과 일부 기능이 완전히 같지 않으므로, 공개 전에 두 종류의 기기에서 실제로 시험해야 합니다.

서로 다른 기기의 친구와 어떻게 함께 플레이할지 아직 정하는 중이라면 [친구와 Minecraft를 함께 하는 방법](/ko/stories/minecraft-play-with-friends/)도 확인하세요.

## 요약: Java + Geyser + Floodgate로 하나의 서버를 함께 쓸 수 있다

직접 관리하는 Java 서버라면 서버 측 플러그인을 지원하는 Paper에 Geyser와 Floodgate를 함께 설치하는 구성이 알기 쉽습니다.

- Java 친구는 Java 서버의 TCP 접속 지점으로 들어옵니다.
- 베드락 친구는 Geyser가 대기하는 UDP 접속 지점으로 들어옵니다.
- Floodgate를 사용하면 베드락 친구가 별도의 Java Edition 계정을 구매하지 않아도 베드락 계정으로 참여할 수 있습니다.
- Java 서버의 online-mode는 true로 유지합니다.

이 방법은 Java 서버에 베드락 연결 경로를 추가하는 것입니다. Java 클라이언트가 베드락 전용 서버에 직접 들어가게 하거나 Java와 베드락 Realms를 서로 연결하는 방법은 아닙니다.

기존 서버가 두 에디션을 모두 받는지 확인해야 한다면 [Java와 Bedrock을 함께 플레이할 수 있나요?](/ko/stories/minecraft-java-bedrock-crossplay/)를 확인하세요.

### 먼저 확인할 사항

- Java 서버를 실행할 수 있는 PC 또는 서버 플러그인을 지원하는 호스트를 준비합니다.
- 모두가 자신이 보유한 에디션에 정상적으로 로그인할 수 있는지 확인합니다.
- 지원되는 Java와 베드락 버전, 설치한 플러그인, 리소스 팩을 맞춥니다.
- 콘솔은 사용자 서버 입력 방식이 기기마다 다를 수 있습니다. DNS 변경 같은 우회 설정은 사용하지 말고, 기기와 호스트의 공식 안내를 확인합니다.

## 무료로 시작하는 구성을 고르기

무료 서버란 서버 소프트웨어나 무료 호스팅 요금이 없다는 뜻입니다. Minecraft 본체, 호스트 PC, 전기와 인터넷, 백업, 업데이트 작업까지 무료라는 뜻은 아닙니다.

| 구성                    | 추가 비용을 보는 방법                         | 멀리 있는 친구를 초대하는 방법                                | 안전하게 시작할 조건                                                  | 주요 제한                                     |
| ----------------------- | --------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------- |
| 집 서버, LAN 전용       | 서버 소프트웨어는 무료                        | 원격 플레이어를 초대하지 않고 집이나 같은 네트워크에서만 시험 | 라우터 공개 설정을 만들지 않음                                        | 집 밖 친구는 들어올 수 없음                   |
| 집 서버, 인터넷 접속    | 소프트웨어는 무료이고 PC, 인터넷, 전기는 별도 | 필요한 범위에서 Java TCP와 Geyser UDP만 허용                  | 허용 목록, OS 방화벽, 백업을 먼저 설정                                | 라우터, IPv6, 업데이트를 직접 관리            |
| 무료 호스트 예: Aternos | 무료 플랜 조건을 따름                         | 호스트가 표시하는 주소와 포트를 사용                          | 호스트 공식 절차로 Paper, Geyser, Floodgate를 설치하고 허용 목록 사용 | 용량, 가동 조건, 지원 플러그인이 바뀔 수 있음 |
| Realms                  | 구독                                          | 초대 기능 사용                                                | 공식 초대와 계정 제어 사용                                            | Java와 베드락 크로스플레이용이 아님           |

집에서 포트를 여는 것이 불안하다면 먼저 LAN에서 구성을 확인하거나, 외부 주소와 포트를 호스트가 관리하는 무료 호스트로 시작하는 편이 안전합니다. 이 글을 작성할 때 Aternos의 공식 안내는 Paper를 권장하고 Geyser를 설치할 때 Floodgate를 자동 설치·설정하는 방법을 설명합니다. 패널이나 정책이 바뀌었다면 현재의 공식 안내를 우선합니다.

Java, Bedrock, Realms의 무료 선택지를 기본부터 비교하려면 [무료 Minecraft 서버를 만드는 방법](/ko/stories/minecraft-server-setup/)도 참고하세요.

## 접속 구성을 이해하기

Java와 베드락은 서로 다른 네트워크 형식으로 서버에 도착합니다. 하나의 Paper 서버에 Geyser와 Floodgate를 설치하면 연결마다 역할이 나뉩니다.

| 접속하는 사람 | 접속 대상                                          | 통신                    | 서버 측 역할                     |
| ------------- | -------------------------------------------------- | ----------------------- | -------------------------------- |
| Java 친구     | Java 서버 주소와 포트                              | TCP                     | Paper가 직접 받음                |
| 베드락 친구   | 같은 호스트 이름과 Geyser용으로 안내한 베드락 포트 | UDP                     | Geyser가 연결을 Paper용으로 변환 |
| 관리자        | 서버 콘솔 또는 호스트 관리 패널                    | 공개하지 않는 관리 경로 | 허용 목록, 백업, 업데이트 관리   |

집에서 운영할 때 일반적인 포트는 Java TCP 25565와 Geyser UDP 19132이지만 호스트는 다른 번호를 할당할 수 있습니다. 베드락 친구에게는 관리 패널에 표시된 Geyser용 UDP 포트를 알려 주고, 19132라고 추측하게 하지 마세요.

Geyser의 UDP 포트는 음성 채팅, Query, 다른 UDP 서비스와 함께 쓸 수 없습니다. 나중에 기능을 추가할 때도 같은 포트를 억지로 재사용하지 말고 공식 문서와 호스트의 포트 할당을 확인합니다.

![왼쪽의 PC Java 플레이어가 보호된 서버 집에 직접 연결되고, 오른쪽의 태블릿·휴대폰·휴대용 게임기의 Bedrock 플레이어가 파란 다리를 지나 같은 집으로 연결되는 모습](/uploads/stories/minecraft-java-bedrock-shared-server-topology.webp)

_Java는 Paper에 직접 연결되고, Bedrock은 먼저 Geyser에 도착한 뒤 같은 Paper 서버로 전달됩니다._

## 단계1: Paper, Geyser, Floodgate 설치

1. Paper처럼 서버 측 플러그인을 지원하는 Java 서버 소프트웨어를 선택합니다. 바닐라 Java 서버만으로는 Bukkit 계열 플러그인을 불러올 수 없습니다.
2. Geyser와 Floodgate는 Geyser 공식 배포처나 사용 중인 호스트의 공식 애드온 화면에서 서버 버전에 맞는 것을 설치합니다. 출처를 알 수 없는 파일은 사용하지 않습니다.
3. 서버를 한 번 시작하고 콘솔에서 Geyser와 Floodgate가 모두 로드되었는지 확인합니다.
4. Paper 플러그인 구성에서는 Geyser가 Java 서버 대상과 Floodgate 인증을 자동 감지할 수 있습니다. 직접 설정을 바꾸기 전에 공식 설정 절차와 호스트별 안내를 확인합니다.

클라이언트에만 설치해야 하는 MOD는 Geyser를 통해 들어오는 베드락 클라이언트에서 동작하지 않습니다. 모두를 초대하기 전에 작은 그룹으로 두 에디션에서 설치한 MOD, 플러그인, 리소스 팩을 시험합니다.

## 단계2: 공개 전에 안전한 기본값 설정

먼저 Paper의 server.properties에서 Java 인증과 허용 목록을 켭니다. 서버 버전이나 호스트 패널에 따라 표기가 다를 수 있으므로 바꾸기 전에 현재 값을 확인합니다.

| 설정              | 권장값 | 이유                                    |
| ----------------- | ------ | --------------------------------------- |
| online-mode       | true   | Minecraft 계정으로 Java 연결을 인증     |
| white-list        | true   | 초대하지 않은 사람의 참여를 막음        |
| enforce-whitelist | true   | 허용 목록에 없는 플레이어를 내보냄      |
| enable-rcon       | false  | 사용하지 않는 원격 콘솔을 공개하지 않음 |
| enable-query      | false  | 사용하지 않는 Query 대기를 늘리지 않음  |

Java 친구는 일반 허용 목록에 추가합니다. 베드락 친구는 본인의 실제 게이머태그로 Floodgate 허용 목록 명령을 사용합니다. 게임 안에서 관리자 권한이 있는 채팅에서는 **/fwhitelist add gamertag**를 실행하고, 호스트의 서버 콘솔에서는 앞의 `/`를 뺀 **fwhitelist add gamertag**를 사용합니다. 이름 접두사를 추측해 일반 허용 목록을 사용하거나, 시험 중 허용 목록을 꺼 둔 채로 두지 마세요.

관리자 권한은 정말 필요한 사람에게만 줍니다. 서버 전체 설정, Floodgate 키 파일, 호스트 로그인 정보를 친구에게 배포하지 마세요. 설정 변경, 플러그인 업데이트, 게임 업데이트 전에 백업하고 복원할 수 있는지도 확인합니다.

![관리자가 방패 옆에서 허용 목록을 확인하고, 두 개의 좁은 파란 경로가 벽을 지나 서버 집으로 이어지며, 별도의 관리용 문은 잠겨 있는 모습](/uploads/stories/minecraft-java-bedrock-shared-server-safe-settings.webp)

_테스트 후 확인한 Java와 Geyser 경로만 허용하고, 관리 경로는 인터넷에 공개하지 않습니다._

## 단계3: 필요한 통신만 단계적으로 공개

외부 접속을 열기 전에 먼저 연결을 시험합니다.

1. 호스트 PC 또는 같은 LAN의 Java 클라이언트에서 Paper 서버에 접속합니다.
2. 같은 LAN의 베드락 클라이언트에서 UDP 포트로 Geyser를 통해 접속합니다.
3. 두 에디션 모두에서 허용 목록, 스폰, 상자, 채팅, 월드 저장을 확인합니다.
4. 원격 친구가 꼭 필요할 때만 OS 방화벽과 라우터에서 Java TCP 포트와 Geyser UDP 포트를 각각 허용합니다.
5. 다른 네트워크의 허용 목록 친구 한 명으로 접속을 시험합니다. Geyser의 connectiontest도 접속 대상을 확인하는 데 도움이 됩니다.

DMZ, 모든 포트 공개, 방화벽 해제, 관리 패널이나 RCON의 인터넷 공개는 필요하지 않습니다. 호스트가 IPv6으로 외부에서 닿는 환경이라면 IPv4 포트 전달만 보고 안전하다고 생각하지 말고, OS 방화벽 규칙이 IPv6에도 적용되는지 확인합니다.

![왼쪽에서 PC와 태블릿 플레이어가 보호된 서버 집 근처에서 시험하고, 중앙의 관리자가 문에서 방패를 확인한 뒤 오른쪽의 원격 친구 한 명이 연결되는 모습](/uploads/stories/minecraft-java-bedrock-shared-server-staged-test.webp)

_먼저 LAN에서 두 에디션을 시험한 뒤, 다른 네트워크에 있는 허용 목록의 친구 한 명으로 외부 접속을 확인합니다._

이 순서로 시험해도 연결되지 않으면 공개 범위를 넓히지 마세요. [Minecraft 서버에 들어갈 수 없을 때 확인할 사항](/ko/stories/minecraft-server-cannot-join/)으로 에디션, 버전, 계정, 네트워크를 순서대로 구분합니다.

## 무료 호스트로 시작할 때의 확인

무료 호스트에서도 공개 범위 원칙은 같습니다. 집 라우터에 포트 전달을 만들 필요는 없지만, 호스트 계정, 허용 목록, 관리 패널 접근은 계속 보호해야 합니다.

1. 호스트 공식 안내에 따라 Java Paper 서버를 만듭니다.
2. 공식 애드온 화면에서 Geyser를 추가하고 Floodgate가 설치되었는지 확인합니다.
3. 서버를 시작한 뒤 호스트의 Connect 화면에 표시된 Java와 베드락 주소·포트를 확인합니다.
4. 친구에게 접속 정보를 개별적으로 알리기 전에 단계2의 인증과 허용 목록 설정을 확인합니다.
5. 새로운 베드락 버전이 나오면 호스트와 Geyser의 공식 안내에서 Geyser 업데이트가 필요한지 확인합니다.

무료 플랜의 가동 조건, 백업 범위, 지원 애드온, 서비스 중단 처리 방식은 제공자마다 다르고 바뀔 수 있습니다. 중요한 월드를 호스트에만 두지 말고 약관과 관리 패널에서 허용하는 방법으로 다른 보관처에도 백업합니다.

## 권장하지 않는 설정

- 베드락을 받기 위해 online-mode를 false로 바꾸지 마세요. Geyser 공식 FAQ는 Floodgate 없는 오프라인 모드를 위험하고 지원하지 않는 방식으로 봅니다.
- 한 번만 시험하더라도 허용 목록을 끈 상태로 서버를 공개하지 마세요. 베드락 플레이어는 Floodgate 허용 목록 기능으로 추가합니다.
- 접속 문제 원인을 찾지 않고 DMZ, 모든 포트 공개, 방화벽 해제, UPnP 자동 공개를 사용하지 마세요.
- 혹시 모르니 RCON, Query, PROXY protocol, 외부 관리 패널을 켜 두지 마세요. 필요한 구성을 이해하고 공개 범위를 제한할 수 있을 때만 검토합니다.
- 출처를 알 수 없는 플러그인, 인증을 우회하는 플러그인, 검토하지 않은 전체 공유 설정을 실행하지 마세요.

## 친구를 초대하기 전 확인 목록

- Java와 베드락 클라이언트 모두 실제 시험에서 접속, 퇴장, 재접속할 수 있었다.
- Java 서버의 online-mode가 true이고 허용 목록이 켜져 있다.
- Java 이름과 Floodgate를 통한 베드락 게이머태그가 각각 알맞은 허용 목록에 들어 있다.
- 인터넷에 공개한 것은 Java TCP와 Geyser UDP뿐이며 RCON, Query, 관리 패널은 공개하지 않았다.
- 친구에게 자신의 에디션에 맞는 주소, 포트, 지원 버전을 개별적으로 알렸다.
- 최신 백업이 있고 업데이트 전에 복원 방법을 확인했다.

이 항목을 확인하면 Java와 베드락 친구가 섞여 있어도 인증과 공개 경계를 지키면서 같은 월드에서 플레이를 시작할 수 있습니다.
