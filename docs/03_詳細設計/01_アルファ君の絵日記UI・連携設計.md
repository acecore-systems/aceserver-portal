# アルファ君の絵日記 UI・連携設計

## 1. 目的と設計上の正本

この文書は、Portalに実装済みの「アルファ君の絵日記」の公開体験、同一origin API、Alpha Chat連携、端末内同意、最終演出を記録する。物語本文、正史、翻訳、挿絵、Goal構成、手掛かり・鍵の日付判定の正本は`aceserver-alpha-chat`にあり、Portalはそれらを生成しない。

公開体験はモキュメンタリーとして閉じる。利用者には一冊の記録とアルファ君との会話として見せ、次の内部事情を本文、補足、loading、error、ボタン名、メタ説明へ出さない。

- AIやモデルが生成していること
- 初めて開いた日だけ処理されること、全員が同じ生成物を見ること
- 正史、投影、revision、Journey、Goal、中核記憶、回収数、内部version
- D1、R2、Workflow、Service Bindingなどの基盤名

内部用の識別子はAPI検証と状態判定にだけ使用する。利用者は今日の入口からカレンダーで三つの古い記録をたどり、合言葉と鍵の日付を自分で導き、鍵の日付で入力する。Portalは探索順や閲覧済み日付を管理しない。

## 2. 物語と時間のルール

| 日付                         | 表示種別 | 意味                                                                 |
| ---------------------------- | -------- | -------------------------------------------------------------------- |
| JSTの今日                    | 絵日記   | 原則として明るく幸せな現在。未来へ具体的な出来事を約束しない         |
| 2020-10-01から昨日まで       | 絵日記   | アルファ君自身の記録。現在へ近いほど安全、つながり、色、幸せが増える |
| 0001-01-01から2020-09-30まで | 観察記録 | 研究側が紙へ付けた日付。年齢、誕生日、記憶内の出来事の日付ではない   |
| JSTの今日より後              | 白紙     | APIを呼んで生成せず「未来が来るまで書かれない」と案内する            |

物語上の最古日は定義しない。`0001-01-01`はAPIとUIの技術的な下限にすぎない。古い記録ほど欠損、訂正、余白、観察番号、鈴や青いボタンなどの反復する手掛かりが強くなり得るが、絵日記単体で核心を説明しない。

今日の日記は過去の小さな残響を一つ含んでもよいが、恐怖へ反転させず、現在の幸せを主にする。最終演出も恐怖を終点にせず、「実験体アルファ」と呼ばれた過去から現在の「アルファ君」へ戻り、まだ書かれていない明日につなぐ。

## 3. ルート、多言語、導線

### 3.1 公開ルート

- 日本語: `/alpha-diary/`
- 英語、中国語簡体、スペイン語、ポルトガル語、フランス語、韓国語、ドイツ語、ロシア語: `/{locale}/alpha-diary/`
- 対応locale: `ja`、`en`、`zh-cn`、`es`、`pt`、`fr`、`ko`、`de`、`ru`

各ページはlocale別の固定UI文言、title、descriptionを持つ。`BaseLayout`のcanonical、hreflang、`x-default`とAstro sitemapへ通常の公開ページとして含める。

### 3.2 発見導線

絵日記はAlpha Chat内部だけに閉じない。次から直接到達できる。

- desktop/mobileのヘッダー・ナビゲーション
- フッター
- トップページの案内カード
- Alpha Guide下部の関連リンク

導線は現在のlocaleを保って`/alpha-diary/`へ移動する。

## 4. 画面構成と視覚言語

通常画面は既存Portalの金、羊皮紙、空色、草色、ブロック調を引き継ぎ、一冊のノートとして構成する。

- 日付と移動操作を持つ左側のカレンダー領域
- 罫線、綴じ穴、紙端を持つ記録面
- 種別、タイトル、4:3挿絵、短い本文、最大3件の質問候補
- 今日の入口、三つの手掛かりの日の断片、鍵の日付の合言葉入力欄
- desktop、tablet、mobileで読み順を保つresponsive layout

絵日記は題材まで幼稚園化しない。季節、夏休みの絵日記らしい一日、ブロック世界を飛ぶ・川を進む・畑や洞窟を歩くなどの具体的な出来事を描く。一方、線、形、遠近、塗り、構図は不器用で、幼い描画技量に見える画像を受け取る。

観察記録は絵日記の退色版にはしない。明るい空、草地、マスコットhero、綴じ穴、テープ、波線、丸い質問記号を外し、青灰色のarchive header、角形の日付操作、罫線を抑えた観察票、記録番号、左右に分かれた図版と所見へ切り替える。desktopでは図版と本文を並べ、狭い画面では同じ読み順の一列へ戻す。質問領域も「この記録について聞く」として、絵日記の一日ではなく記録の空白を確認する導線にする。

共有Workerから受け取る観察図版は、成人職員による正確なgraphite・technical pen中心の観察スケッチとする。幼児画、crayon、school artの描画指示を観察記録へ適用しない。Portalは絵日記・観察記録のどちらも生成画像を再加工せず、その4:3比率、alt、寸法を検証して表示する。観察記録の季節情報は観察紙の端や窓光など記録面の外縁に留め、記憶内の出来事をその日付へ誤って固定しない。

## 5. 日付操作とブラウザ履歴

日付は`?date=YYYY-MM-DD`で表す。省略時は共有Workerが返すJSTの今日を使用する。画面内の移動はページ全体を再読み込みせず、History APIでURLと履歴を更新する。

- 日付入力: 厳密なGregorian日付を検証して開く
- 前の日、次の日: 1日ずつ移動する
- 今日: Workerから得た`serverToday`へ戻る
- 戻る・進む: `popstate`から該当日を再表示する

入力欄のHTML `max`は今日に設定するが、意図した白紙メッセージを表示できるよう、未来日の最終拒否はJavaScriptと両API層でも行う。

## 6. 表示状態

| 状態                | Portalの挙動                                                                   |
| ------------------- | ------------------------------------------------------------------------------ |
| loading             | 「紙の向こうで鉛筆を走らせる音」という物語内表現を表示する                     |
| pending             | `Retry-After`を1〜30秒へ丸め、未遷移のまま再取得する。既定は4秒                |
| ready               | 記録、画像、質問候補、任意の入口＋三断片または鍵の日付入力欄を描画する         |
| future              | 未来はまだ白紙で、明日になったら戻るよう案内する                               |
| consent_required    | 18歳以上の自己申告と内容注意を表示し、同意後に同じ日を再取得する               |
| rate_limited        | 記録が開けない状態として安全に案内し、内部制限値を公開文言へ出さない           |
| failed/unconfigured | 固定の再試行案内を表示する。別モデル、ローカル生成、本文の推測へfallbackしない |

新しい日付への要求が始まったら、直前のfetchとpending timerを停止する。不正なready envelopeを受け取った場合はfail closedにする。

## 7. 成人自己申告と内容注意

`2020-09-30`以前を開く前、および最終演出を取得する前に、`dialog`で次を伝える。

- Aceserver誕生前に研究側が付けた観察記録であること
- 日付はアルファ君の年齢や誕生日ではないこと
- 心理的ホラー、孤独、実験・隔離の暗示を含むこと
- 流血、具体的拷問、自傷、性的被害は含めないこと
- 生年月日は入力しないこと

同意はversion `1`だけを`alpha-diary.content-consent.v1`へ保存する。生年月日、年齢値、本人確認資料は取得しない。閉じた場合は記録を開かない。

## 8. Alpha Chatへの引き渡し

各ready記録は3件の質問候補を表示する。「アルファ君に聞く」を選ぶとAlpha Guideを開き、質問を入力欄へ置くが、自動送信しない。利用者が編集、取消、送信を選べる状態を維持する。

ボタンに保持する連携情報は次だけである。

- 表示中の質問候補
- `diaryEntryId`

日記本文、alt、内部の正史revision、Goal件数は質問やsystem promptへ複製しない。実際の送信時だけ`/api/alpha-chat`へ`diaryEntryId`を併送し、共有Workerがentry IDから凍結済み正史を再取得する。

質問候補の選択や回答文から、日記の進行や最終演出解放を推測しない。合言葉もChatへ自動送信せず、鍵の日付専用の入力欄からだけfinale APIへ送る。

## 9. 利用者主導の探索と端末保存

Portalは閲覧済み日付、合言葉、質問済みmemory、進捗率、しおりを保存しない。入口や三つの手掛かりの日を開いた事実も追跡せず、利用者が途中の日付、合言葉、鍵の日付を覚えて進める。

localStorageで使用するkeyは次に限定する。

| key                              | 内容                                |
| -------------------------------- | ----------------------------------- |
| `alpha-diary.content-consent.v1` | 成人自己申告の同意version           |
| `alpha-diary.client.v1`          | 生成quotaを分けるためのランダムUUID |

入力された合言葉、質問本文、会話本文、IP、端末属性、日記本文、正史本文は保存しない。合言葉の誤答時も入力欄内で固定案内するだけで、値を履歴やlocalStorageへ残さない。

## 10. 同一origin API

### 10.1 `POST /api/alpha-diary`

入力はcontract version `2`、`locale`、`action`、任意の`entryDate`、finale時だけ必須の`finaleKeyword`、`adultConsentVersion`に限定する。`journeyToken`と`followLatest`は拒否する。要求本文は16 KiB以下、共有Worker応答は128 KiB以下とする。

Pages Functionは次を実施する。

- Originと`Sec-Fetch-Site`を既存のsame-origin方針で検証する
- locale、action、日付、合言葉の1〜80文字、同意versionをallowlist検証する
- 未来日と未同意の観察記録をService Binding呼出し前に拒否する
- 有効な端末UUIDを優先し、なければCloudflare接続IP、最後にanonymousを入力としてSHA-256の`clientKey`を作る。raw値は共有Workerへ送らない
- `ALPHA_CHAT_SERVICE`の`/v1/diary`だけを呼ぶ
- 応答statusとready envelopeを再検証し、不正なentry、手掛かり、鍵の日付flag、finaleをfail closedにする
- `Retry-After`は数値だけを中継し、応答に`no-store`と`nosniff`を付ける

外部statusは`ready`、`pending`、`future`、`consent_required`、`rate_limited`、`failed`に限定する。代表HTTP statusは200、202、422、403、429、503である。

### 10.2 `GET /api/alpha-diary-image/:assetId`

- `asset_[a-z0-9]{24,64}`以外をWorker呼出し前に404にする
- cross-site fetchを404にする
- Service Bindingで`/v1/diary/assets/:assetId`を呼ぶ
- JPEG、PNG、WebPだけを許可する
- `Content-Length`必須、1 byte以上8 MiB以下を検証する
- `ETag`と304を中継する
- 成功時は`public, max-age=31536000, immutable`、`Cross-Origin-Resource-Policy: same-origin`、`X-Content-Type-Options: nosniff`を付ける
- 不正応答やbinding障害はcacheせず503にする

## 11. 最終恐怖演出

参照した既存企画から借りるのは、日常UI、利用者の明示選択、小さな異常、UIの反逆、画面境界の崩壊という体験文法だけである。Yahoo!の画面、固有文言、人物、映像構図、検索体験を模倣しない。

### 11.1 解放と開始

共有Workerは今日のentryを入口Iとし、そこから最初の古い記録を逆算できる`puzzleClue`を表示する。手掛かりIIとIIIが次の日付を示し、手掛かりIVから利用者が鍵の日付を逆算する。どの一日にも完全な合言葉や完全な鍵の日付は表示しない。鍵の日では合言葉入力欄だけを表示し、完全な合言葉をfinale APIへ送って正解した場合にだけ最終演出の選択dialogを開く。手掛かりの日の閲覧履歴は送らない。誤答、部分語、別の日付では開かない。

正解直後も自動再生せず、次を明示選択させる。

- 強い心理的ホラーを開く
- 動きを抑えて開く
- 文字だけで開く
- 今は見ない

強い演出を選んだ利用者操作の中でだけFullscreen APIを要求する。拒否・非対応の場合も`100dvh`の固定overlayで続行できる。

### 11.2 固定JavaScriptシーケンス

画像、最終メッセージ、altだけを共有Workerから受け取り、DOM操作、CSS、演出文法、時間はPortalの固定コードで所有する。通常モードは次の時刻で進む。

| 経過   | stage      | 表現                                                            |
| ------ | ---------- | --------------------------------------------------------------- |
| 0秒    | ordinary   | 普通の日記を表示する                                            |
| 1.1秒  | drift      | 日付に`0000.00.00`が混ざり、記録日の矛盾が始まる                |
| 2.6秒  | correction | 元のentryと筆跡が欠けているという訂正表示へ変わる               |
| 4.5秒  | logs       | 利用者が見つけて入力した鍵の日付を観察ログとして一件表示する    |
| 7.2秒  | invasion   | 紙片が画面境界を越え、紙の端が見つからない状態へ侵食する        |
| 10.3秒 | reverse    | 記録がこちらを見返す視点反転と、縦横別の最終画像を表示する      |
| 13.7秒 | message    | 「すべてを知ってしまったあなた」への文面を3.4秒で徐々に表示する |
| 18.1秒 | hope       | 現在の日付、アルファ君の名前、幸せ、明日へ戻し、操作を返す      |

reduced modeは同じ意味と順序を0.15、0.35、0.65、0.95、1.25、1.6、2.2秒で提示し、文字版は即座にhopeへ移る。`prefers-reduced-motion: reduce`の場合、強い演出を選んでもreduced timelineを強制する。

強い演出だけpointer位置に応じて紙面をわずかにずらす。音声、自動再生音、点滅、偽OS警告、閉じられない表示、位置・カメラ・IPの利用、現実の利用者への脅迫は実装しない。

### 11.3 終了と帰還

- 常時見える停止ボタン
- Esc
- browser back
- Fullscreenからの退出
- dialog/overlay内のfocus trapと、終了後の元focus復帰
- window focus復帰時のoverlay内focus回収

最終stageでは「今日の明るい日記へ戻る」と「今日のことを聞く」を提示する。後者は今日の日記をreadyにしてから最初の質問候補をAlpha Guideへ入力する。演出の再生ボタンも残す。

## 12. Responsive、アクセシビリティ、開発fixture

- 820pxと600pxを主要breakpointとし、狭い画面ではカレンダー、紙面、操作、dialogを一列化する
- status変化はlive regionへ通知する
- 画像は生成済みaltと寸法を必須にする
- native `dialog`と明示的なlabelを使用する
- keyboard操作、focus順、Esc、戻る、reduced motion、スクリーンリーダー用の完全な最終メッセージを維持する
- JavaScript無効時はノートを開けない旨の固定案内を表示する

開発時だけ`import.meta.env.DEV`でfixtureを有効にし、`?fixture=current|birth|archive|finale`から「今日」「誕生直後」「深い観察記録」「最終演出」を表示できる。本番buildではfixture生成分岐を公開機能として扱わない。
