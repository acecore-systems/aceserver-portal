# トップページのコミュニティ表示

トップページは、公開中の集計値、過去の写真・確認済み投稿、Discordの公開対象の告知とイベント、CMSに登録した一般案内を表示する。公開データの取得に失敗したことを「サーバー停止」や「0人」と読み替えない。

## 表示と出典

| 表示                      | 出典・更新方法                                                                                                          | 表示上の意味                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Discord参加者・オンライン | 本番は既存Discord Workerの専用読み取りentrypoint。preview・日次収集は固定の公開招待API、失敗時は公開widgetを1回だけ参照 | Discordが返す概数。widgetのみ取得できた場合はオンラインだけ表示し、参加者は不明とする                                    |
| ワールド別接続人数        | 各 `https://mc-map-{host}.acecore.net/standalone/dynmap_world.json` の `currentcount` と `timestamp`                    | 公開マップの観測値。ゲームに接続できる保証ではない。ワールド間の総和は表示しない                                         |
| Discordイベント・お知らせ | `DISCORD_COMMUNITY_SERVICE` の `GET https://community.internal/v1/community`                                            | 指定お知らせチャンネルの最新5件と、公開範囲の予定・開催中イベント最大8件。本文は原文のプレーンテキストと出典リンク       |
| CMSイベント               | `src/content/pages/top.json` の `community.events`                                                                      | 追加の確認済み開催情報。空欄をDiscordに予定がない根拠にしない。終了後は閲覧中も非表示                                    |
| 日付のないお知らせ        | 既存 `src/content/site/announcements.json`                                                                              | 開催日を作らず、一般案内として管理。既存の公開期間制御を使う                                                             |
| 建築ギャラリー            | `top.json` の `community.gallery`                                                                                       | `archive` / `current` と撮影時期の注記を必須とする。過去画像は現在の地図へリンクしない。作者・作品名・撮影日は捏造しない |
| 公式X選抜投稿             | `top.json` の `community.xPosts`                                                                                        | 公式アカウント `acecores` の投稿URL・実際の日時・ラベル。閲覧者の操作後に埋め込みを読み込む                              |
| マップ                    | `top.json` の `community.mapWorld`                                                                                      | 最初は抽象的な案内。過去画像を現在地図のプレビューに使わず、操作後に公開Dynmapを読み込む                                 |

ホストの固定対応は `main`, `sigen`（resource）, `rpg`, `lobby`, `rpg-sub`, `season-a`, `season-a-c`, `event`。取得先を閲覧者やCMSから自由に指定することはできない。

## 現在値の取得

同一originの `GET /api/community-status` が、Discord専用serviceと8つの公開マップを並行取得する。マップは1ソース6秒、serviceは8秒、本文は1 MiBを上限とし、redirectを許可しない。previewと日次収集にはservice bindingを設定せず、公開招待API（2.5秒）→公開widget（2.5秒、1回だけ）の順で集計値を取得する。429の場合はwidgetへ追加取得しない。

レスポンスは人数・取得日時・マップ更新日時・取得状態と、許可された告知・イベント項目だけを新しいobjectに書き出す。Dynmapの `players` / `updates`、チャット、プレイヤー名、Discordプロフィールは返さず、ログにも記録しない。widgetのメンバー一覧も破棄する。

edge cacheは60秒、ブラウザcacheは30秒。ページ表示時の取得は1回とし、手動更新も最短60秒に制限する。公開マップの更新が5分を超えた場合は古い情報として表示し、0人を失敗に置き換えない。タブを開いたままにした場合も通信を増やさず表示の鮮度を再判定する。

人数・お知らせ・イベント・各マップの失敗は独立させる。取得成功時の空配列だけを「該当なし」とし、未設定・取得失敗を予定なしに読み替えない。マップの更新確認はMinecraftの接続試験ではない。参加先や対応版の現在案内はDiscord/WIKIを正とする。

人数取得が失敗した場合、edge cacheにある最後の成功値を元の取得日時のまま最長6時間だけ表示する。ブラウザの通信失敗時も取得済み値を同じ上限で保ち、古い値であると表示する。失敗しても日時を現在に書き換えない。cache消失や6時間超過では値を消し「取得できませんでした」とするため、永続的な可用性保証ではない。

2026-10-15 17:40 JSTごろの取得不可報告は、その後の公開API確認では再現しなかった。旧実装は失敗理由を保存しておらず、当該時点のHTTP原因は特定できない。今回の対応は単一招待API依存と、更新失敗時に成功値を失う既知の弱点への修正であり、過去の原因を断定するものではない。

## Discord専用サービス

本番だけ `DISCORD_COMMUNITY_SERVICE` を `aceserver-alpha-discord-production` のnamed entrypoint `PortalCommunityFeed` へ接続する。既存Worker側で先にentrypointを公開してから、このPortalのGitHub連携デプロイを行う。previewは未設定のまま、Discordで確認する案内を表示する。PortalへBot tokenを渡さず、新規Botや権限は追加しない。

許可対象はguild `737538781024092170`、お知らせchannel `774152638450237460`。お知らせはid・本文（最大2000字）・投稿日時・同channelの正規メッセージURL、イベントはid・名前（最大100字）・説明（最大1000字、空可）・開始日時・終了日時（null可）・同guildの正規イベントURLだけを受け入れる。本文は `textContent` で描画し、外部HTMLやMarkdownとして実行しない。原文は自動翻訳せず、UIラベルのみ9言語化する。

Worker側でユーザー・ロール・チャンネルへのメンションIDと `@everyone` / `@here` を除去する。Portal側でも残存メンションを拒否し、author・member・attachmentなど契約外のフィールドを捨てる。終了日時があるイベントは閲覧時にも終了判定する。終了日時がない開催中イベントの終了判定はDiscordの公開状態を正とする。

2026-10-15 18:11 JSTに、Alpha PR #154のmain `1980316`、Discord Worker version `8ef61160-36f7-4ec5-9066-634dc933591f` でnamed entrypointの実取得を確認した。人数1465/105、告知5件、イベントは取得成功で0件。公開URLの `/v1/community` は404で、entrypointは公開ルートとして露出していない。この確認はPortal本番へのbinding反映とは別である。

## 日次履歴の収集・公開

`collect-community-activity.yml` は毎日03:17 UTC（12:17 JST）に実行予定で、GitHub Actionsの都合により遅延・欠測があり得る。実測時刻は各観測点の `observedAt` を正とする。

`npm run sync:community` は公開集計値だけを収集し、日付ごとに1点、最大31日分を保存する。同日再実行は後の観測で置き換える。古いマップ値・取得失敗は `null` にし、0人と分ける。widgetだけ取得できた日はonlineだけを保存する。前回成功値を新しい観測点として再保存しない。欠測を補間せず、2点以上そろうまで折れ線を描かない。人数・時刻以外のsource payloadは保存しない。

定期workflowは専用branch `automation/community-daily-activity` にスナップショットだけをcommitし、Draft PRを作成または更新して `ci.yml` を起動する。自動マージは行わない。レビュー中も、そのbranchの差分が履歴JSONだけであることを確認したうえで、そのJSONのみをmain側の収集コードへ渡す。これにより、未マージPR中に集めた過去点が次の日の収集で消えない。想定外の差分や壊れた履歴では停止する。

更新時は最新のmainを専用branchへmergeしてから履歴を反映し、CIもそのmainコードで実行する。競合が履歴JSONだけの場合は検証済み集計値を採用し、他ファイルの競合ではpushせず停止する。最終PR差分が履歴JSONだけであることも再検証する。remote branchの強制更新は行わない。

**取得時刻と公開時刻は異なる。** 新しい履歴は更新PRのマージとGitHub pushに連携したPagesビルドが成功した後に公開される。PRのレビュー待ちの間は公開グラフは更新されないが、専用branch上の収集は続く。現在値APIはその待ち状態と独立して取得する。

初期履歴は収集スクリプトによる実測1点から開始する。履歴の期間・日次頻度・保存項目を変更するときは運用変更として別途レビューする。新規provider、認証情報、外部ストレージは不要。

## CMSと翻訳

写真・追加イベント・X投稿の編集は「ポータルページ → トップページ → トップページのコミュニティ表示」で行う。一般案内は既存「お知らせ」で管理する。`community` はトップ専用で、gallery/event/postのIDを重複させない。Xは公式アカウントの正規URL、写真は `/uploads/` 配下、現在写真のリンクは公開済み内部ページ、追加イベントはタイムゾーン付きの開始・終了日時とHTTPS URLが必要。

初期の飛行船・街並み画像は過去の風景で、現在のワールドにその場所はない。撮影時期は未確認のため「撮影時期不明」と明示する。背景にも過去画像の注記を表示する。`archive` にhrefを設定するとvalidatorが拒否する。

日本語の公開文面や項目を変更した場合は `src/i18n/translations.ts` の `community` に8言語を反映し、固定コンテンツの `sourceHash` を更新する。状態ラベルは `src/data/community-ui.ts` の9言語を揃える。`npm run validate:content` がID・翻訳shape・hash・画像参照を検証する。

Xとマップは操作前に外部iframeを作らない。X埋め込みの表示が制限される場合も、実投稿へのリンクを残す。CSPはXのframe originだけを追加し、外部scriptは追加しない。
