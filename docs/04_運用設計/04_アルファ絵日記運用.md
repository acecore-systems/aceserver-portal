# アルファ絵日記運用

## 1. 運用境界

Portal側の運用対象は、公開route、固定UI、同一origin API、Service Binding、Chat handoff、端末状態、固定最終演出である。本文・画像の再生成、正史、Goal、D1 migration、R2、Workflowは`aceserver-alpha-chat`側の運用手順に従う。

運用中の案内もモキュメンタリーの外側を公開画面へ持ち込まない。生成待ち、共有キャッシュ、モデル版、Goal数などを説明する文面を応急表示として追加しない。障害時は既存の「ページがくっついている」固定表示でfail closedにする。

## 2. 変更時の確認

Portal変更では最低限、次を実行する。

```powershell
npm run format:check
npm run test:alpha
npm run typecheck:functions
npm run validate:content
npm run build
git diff --check
```

文面を変更した場合は9言語のkey集合、公開コピー禁止語、canonical/hreflang/sitemapを確認する。APIを変更した場合はrequest/response上限、未来日と同意の事前拒否、Service Binding以外へのfallbackがないことを確認する。

## 3. fixtureによる視覚確認

ローカル開発で次をdesktop/mobileに表示し、通常Portalと並べて確認する。

- `?fixture=current`: 今日の明るい日記
- `?fixture=birth`: 2020年10月1日の絵日記
- `?fixture=archive`: 深い観察記録
- `?fixture=finale`: 解放後の選択dialogと最終演出

確認点は、幼い描画技量が題材の幼稚化になっていないこと、季節と一日の行動が読み取れること、本文が一つの短い日記に収まること、古い記録ほど欠損と不穏さが増すこと、最後に今日の幸せへ戻ることである。

## 4. Previewと本番の反映順

1. 共有Workerの対象version、production flag、D1 migration、R2、Workflow、secretの存在をAlpha Chat側で確認する。
2. PreviewのPortalへService Bindingを設定し、今日、境界日、観察記録、未来、pending、画像、Chat handoff、最終演出を確認する。
3. Portal PRを`main`へ取り込み、GitHub連携のCloudflare Pages deploymentを待つ。Direct Uploadを本番完了条件にしない。
4. Git Provider: Yes、source repository、source SHA、`github:push`成功、custom domain activeを個別に確認する。
5. `https://asv.acecore.net/alpha-diary/`と代表localeを外部から開き、本番smoke testを行う。

WAFはリポジトリ設定からactive状態を断定できない。運用上の初期基準は`POST /api/alpha-diary`をIP単位10 requests / 10 seconds超で60秒block、`GET /api/alpha-diary-image/*`を120 requests / 60 seconds超でmanaged challengeまたは短時間blockとする。実際のtrafficに合わせて変える場合は、DashboardまたはCloudflare APIで対象rule、式、閾値、期間、action、active状態を別途確認する。日記連携を理由に既存`/api/alpha-chat`のclient 5件/分、global 60件/分のアプリ側制限を緩和しない。

## 5. 本番smoke test

- 日付省略がJSTの今日を開き、明るい内容と画像を表示する
- `2020-10-01`が絵日記、`2020-09-30`が同意後の観察記録になる
- 未来日がWorker生成を開始せず、白紙と明日の案内になる
- pending中に同じ画面で再確認し、二重表示や連続送信を起こさない
- 画像がsame-originで表示され、ETag再要求が304になる
- 質問候補がChat入力欄へ入るだけで、自動送信されない
- 送信後にallowlist済みeventだけで進行表示が更新される
- header、mobile menu、footer、top page、Alpha Guideから絵日記へ到達できる
- 通常、reduced、textの最終演出を開始・停止でき、Fullscreen拒否時も閉じられる
- 今日へ戻る二つの操作が正しく動く
- 公開文面にAI生成、共有、Goal、version、回収数などの舞台裏がない

実際の未知の正史を作る質問はsmoke testに使わない。既存の安全な記録と通常案内で連携を確認する。

## 6. 障害切り分け

| 症状                   | Portalで確認するもの                                     | Alpha Chat側へ引き渡す証跡                               |
| ---------------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| 全日付がfailed         | Pages source SHA、Service Binding、Function log          | request ID、時刻、Worker version。本文やtokenは除く      |
| 一日だけpendingが継続  | `Retry-After`、同一日への重複fetch、browser console      | entry ID、status、lease/failure code                     |
| 画像だけ表示されない   | asset ID形式、HTTP status、Content-Type/Length/ETag      | asset ID、D1 metadataとR2 metadata/hashの照合結果        |
| Chatだけ答えない       | `/api/alpha-chat` status、送信時のlinked field有無       | diaryEntryIdと一般化したerror code。質問本文は保存しない |
| 解放されない           | allowlist event、更新token、現在日再取得                 | opaque memoryのseen/chatted状態。回答文字列で判定しない  |
| 最終演出を閉じられない | Esc、stop、back、fullscreenchange、focus、reduced motion | browser/OS、viewport、再現手順                           |

token、質問本文、会話本文、IP、生年月日をissue、PR、ログ、スクリーンショットへ記載しない。

## 7. ロールバック

- Portalだけの異常は、GitHub連携Pagesの直前の正常commitへforward fixまたはrevertする。
- 共有Worker異常時はAlpha Chat側で`ALPHA_DIARY_ENABLED=false`を反映し、通常Alpha Chatを維持する。Portalはローカル生成へ切り替えない。
- D1やR2の削除、migration巻き戻しはPortal運用から行わない。
- 「しおりを外す」は利用者端末のJourney tokenとopened datesだけを消す操作で、共有された日記や正史を削除しない。
