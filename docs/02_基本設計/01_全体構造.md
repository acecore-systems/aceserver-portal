# 全体構造

## 構成

| 区分                         | 役割                                                 |
| ---------------------------- | ---------------------------------------------------- |
| Astro / Tailwind CSS v4      | 公開ページと多言語ページを生成する                   |
| Content Collections          | 読みもの、ページ、サイト設定を構造化して保持する     |
| Sveltia CMS                  | CMS管理対象のページ・サイト設定・メディアを編集する  |
| Cloudflare Pages / Functions | GitHub連携による公開とCMS保存の同一origin検証を行う  |
| 共有Alpha Chat               | Private Service Binding経由で案内チャットを提供する  |
| アルファ君の絵日記           | 日付別記録を表示し、質問をAlpha Chatへ引き渡す       |
| Vectorize                    | WIKI、Portal、関連サイトの公開情報を用途別に検索する |

## 公開と情報の扱い

1. コンテンツはPull Requestまたは検証済みCMS保存で`main`を更新する。
2. Cloudflare PagesがGitHub連携で公開する。
3. 検索は用途ごとのindexを分離し、根拠を異なるサイト間で混同しない。
4. Previewは検索kill switchとフォールバックにより、Production前提の検索を有効にしない。

## 絵日記の責務分担

```text
利用者
  ├─ /{locale}/alpha-diary/?date=YYYY-MM-DD
  │    ├─ POST /api/alpha-diary
  │    │    └─ ALPHA_CHAT_SERVICE → /v1/diary
  │    └─ GET /api/alpha-diary-image/:assetId
  │         └─ ALPHA_CHAT_SERVICE → /v1/diary/assets/:assetId
  └─ Alpha Guideへ質問を入れる
       └─ POST /api/alpha-chat → /v1/chat
            └─ diaryEntryIdと署名済みjourneyTokenを任意で併送
```

- Portalはルート、固定UI文言、表示状態、成人自己申告、ブラウザ履歴、Alpha Guideへの入力、最終演出のJavaScriptを所有する。
- 共有Workerは日付判定、正史投影、本文・翻訳・画像生成、審査、D1/R2/Workflow、Journey/Goal判定を所有する。
- ブラウザは共有WorkerやR2を直接呼ばない。Pages Functionが同一originと入出力を検証し、Private Service Bindingだけで中継する。
- 絵日記を開くこと自体は正史を増やさない。日記に紐付いた質問を利用者が実際に送信した場合だけ、共有Workerが既存正史の再取得と追加可否を判定する。

## UI スタイル基盤

- Tailwind CSS v4 は `@tailwindcss/vite` を Astro の Vite 設定へ組み込む。
- `src/styles/global.css` の `@theme` を色、書体、重み、遷移時間の唯一の共通トークン定義とする。
- 既存画面で使う共通ボタン・パネルは同ファイルの `@utility` として定義し、UnoCSS は併用しない。
- Tailwind Preflight を採用する。サイト固有の最小幅、アンカー位置、フォーカス、reduced motion、表の可読性は `@layer base` で明示的に補う。
